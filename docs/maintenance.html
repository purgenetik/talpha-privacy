Maintainer Guide

Release rule

Documentation should describe the tagged source release.

For v3.0, the source metadata are:

versionCode = 18
versionName = 3.0

Release checklist

  1. Verify calculator reference cases.
  2. Verify versionCode and versionName.
  3. Test debug build.
  4. Test minified release build.
  5. Test Google Play Billing entitlement.
  6. Test Free-version advertising.
  7. Test history save/load/delete/share.
  8. Test personal logo.
  9. Test nuclear-database update from the previous database version.
  10. Test offline fallback.
  11. Test Summary Scheme Index.
  12. Test representative nuclide layers.
  13. Test zoom/pan and clickable regions.
  14. Test alpha-decay schemes with multiple excited levels.
  15. Test a nuclide with no usable ENSDF transition data.
  16. Verify transfer of A, Z, branch Qα, Eexc and l=0 to calculator.
  17. Update CHANGELOG.md.
  18. Update affected docs/*.md.
  19. Verify NDFS PDF links.
  20. Commit, tag and push the release.

Scientific code

Changes to AlphaDecayCalculator.kt are scientifically significant. Do not mix coefficient/formula changes into cosmetic refactoring without explicit validation and changelog documentation.

Database reader

Changes to:

NuclideDatabase.kt
NuclideDatabaseUpdater.kt

can affect compatibility and safe updates.

If a change alters the formal database schema rather than only the Android implementation, revise the NDFS specification as a separately versioned controlled document.

ENSDF renderer

Changes to AlphaDecayScheme.kt can affect how imported evaluated data are interpreted for display.

Pay particular attention to:

  • dataset ID joins;
  • daughter-level energy;
  • duplicate-level handling;
  • experimental half-life association;
  • missing-data fallback;
  • branch Qα calculation;
  • l handling.
