Application Architecture

Build configuration

The supplied 5.0-line source snapshot declares the following Android build metadata:

applicationId = com.purgenetik.talpha
minSdk        = 24
targetSdk     = 37
versionCode   = 27
versionName   = 5.0
Java/Kotlin   = 17

The project uses Kotlin, Jetpack Compose and Material 3.

Main Kotlin modules

AlphaDecayCalculator.kt

Scientific numerical core for the 2009/2010 and 2015 half-life models.

HistoryStorage.kt

Persistence and parsing of .talpha calculation histories.

NuclideDatabase.kt

NDFS parsing, streaming ZIP installation, local DB_vN/DB_vN_A.json storage, layered-database validation and single-layer reads.

NuclideDatabaseUpdater.kt

Remote manifest retrieval, version comparison, temporary download, layered installation and local fallback.

NuclideDatabaseViewModel.kt

Owns lightweight database metadata and at most one selected NuclideLayer. Layer reads run on Dispatchers.IO; an obsolete request is cancelled when the user selects another mass number.

NuclideSummary.kt

Scrollable Summary Scheme Index of available mass-number layers.

NuclideChart.kt

Interactive Canvas renderer for one isobaric layer of potential alpha emitters, including zoom/pan, hit testing, Qα and experimental half-life annotations.

AlphaDecayScheme.kt

Conversion of normalized experimental transitions and NDFS v3.0 adopted levels into drawable daughter levels, SHORT/FULL RANGES filtering and interactive scheme rendering.

MainActivity.kt

Application orchestration and most UI integration, including:

  • calculator;
  • drawer;
  • Premium/Billing;
  • AdMob;
  • history dialogs and sharing;
  • database startup loading;
  • Chart navigation;
  • alpha-decay scheme selection;
  • personal logo;
  • fixed header/footer.

Failure boundaries

The implementation deliberately contains fallbacks at several points:

  • remote update failure → use latest local database;
  • interrupted/invalid installation → discard the staging directory and keep installed versions untouched;
  • obsolete layer request → cancel it and accept only the most recently requested A;
  • local database failure → Chart unavailable, calculator remains separate;
  • malformed/unexpected alpha-decay/adopted-level structure → conventional decay scheme;
  • missing optional experimental fields → omit corresponding annotations.

UI structure in v5.3

The main application has a fixed header, a central content area, and a fixed footer.

The central content area switches among:

calculator
Summary Scheme Index
Nuclide Chart
Alpha Decay Scheme

rather than creating separate Android activities for each scientific view.

Database information is retained across normal Activity recreation by NuclideDatabaseViewModel; the selected layer is released when the chart is closed. This prevents repeated full-database initialization and sharply reduces peak memory use during chart navigation.
