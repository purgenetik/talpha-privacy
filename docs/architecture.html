Application Architecture

Build configuration

The supplied v3.0 source declares:

applicationId = com.purgenetik.talpha
minSdk        = 24
targetSdk     = 37
versionCode   = 18
versionName   = 3.0
Java/Kotlin   = 17

The project uses Kotlin, Jetpack Compose and Material 3.

Main Kotlin modules

AlphaDecayCalculator.kt

Scientific numerical core for the 2009/2010 and 2015 half-life models.

HistoryStorage.kt

Persistence and parsing of .talpha calculation histories.

NuclideDatabase.kt

NDFS JSON/ZIP loading, Kotlin data model and local database discovery.

NuclideDatabaseUpdater.kt

Remote manifest retrieval, version comparison, safe download/install and local fallback.

NuclideSummary.kt

Scrollable Summary Scheme Index of available mass-number layers.

NuclideChart.kt

Interactive Canvas renderer for one isobaric layer, including zoom/pan, hit testing, Qα and experimental half-life annotations.

AlphaDecayScheme.kt

Conversion of normalized alpha-decay JSON into drawable daughter levels and interactive alpha-decay scheme rendering.

MainActivity.kt

Application orchestration and most UI integration, including:

  • calculator;
  • drawer;
  • Premium/Billing;
  • AdMob;
  • history dialogs and sharing;
  • database startup loading;
  • Chart navigation;
  • alpha-decay scheme selection;
  • personal logo;
  • fixed header/footer.

Failure boundaries

The implementation deliberately contains fallbacks at several points:

  • remote update failure → use latest local database;
  • local database failure → Chart unavailable, calculator remains separate;
  • malformed/unexpected alpha-decay structure → conventional decay scheme;
  • missing optional experimental fields → omit corresponding annotations.

UI structure in v3.0

The main application has a fixed header, a central content area, and a fixed footer.

The central content area switches among:

calculator
Summary Scheme Index
Nuclide Chart
Alpha Decay Scheme

rather than creating separate Android activities for each scientific view.
